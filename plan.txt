CaseBreaker: Phase-by-Phase Implementation Plan
Context
The /game directory has a fully working Next.js app with one hardcoded mystery (Harlow Manor). The PLAN.md describes extending this into a daily multi-case pipeline with a FastAPI backend. The old Python backend was deleted; we are building it fresh. User wants to work phase by phase and verify each phase before proceeding.

Tech decisions locked in:

LLM: claude-haiku-4-5-20251001 for all backend generation + interrogation
Interrogation max_tokens: 120 (story generation stays at 3000–4000 to fit full JSON)
Backend: /backend directory in same repo alongside /game
RAG: Include ChromaDB from Phase 1 (world state Layer 1 + Gutenberg Layer 2)
DB: SQLite via aiosqlite
Timing estimate: ~5–10 min total for 3 daily stories (Tripo runs parallel across stories)

No backend exists; all deleted files are staged (not committed)

Architecture notes
architect.py: Single Claude call asking for all 3 mystery worlds in one structured JSON response. Retries up to 5× if consistency fails.
consistency.py: Re-uses the logic from the deleted backend — checks killer alibi, innocent alibis, evidence sources, motive coherence.
novelty_guard.py: Store per-slot fingerprint (setting hash + killer pattern + motive family + summary embedding). Cosine distance < 0.3 from any prior slot → regenerate.
daily_job.py: runs at midnight UTC; generates 3 slots serially; embeds each into its own ChromaDB collection world_{slot_id}; publishes only fully valid slots.
world_embedder.py: Chunks character profiles, timeline events, evidence descriptions → embed with text-embedding-3-small or Claude's embeddings.
literary_embedder.py: Gutenberg corpus (20–30 mystery texts) → chunked, embedded into literary_corpus collection. Run once via scripts/ingest_gutenberg.py.

Phase 2: Keyword System
Goal: Extract dynamic keywords from today's 3 stories; match user selections to best slot.

Changes
backend/agents/keyword_extractor.py — Claude call after generation: extract 10–15 keyword chips (setting, motive type, relationship dynamic, clue style, emotional tone, era) from the 3 combined stories. Return as { keywords: [{id, label, category}] }.
backend/db/schema.sql — Add keywords table: (keyword_id, label, category, slot_scores JSON, date)
backend/api/routes.py — Update GET /daily-slots to include daily_keywords array; add POST /daily-slots/match (body: {selected_keyword_ids: [...]}).
Matching logic: Score each slot by how many of its story features map to selected keywords → return { matched_slot_id, slot_summary }.
Verification
curl http://localhost:8000/daily-slots | jq '.daily_keywords'
curl -X POST http://localhost:8000/daily-slots/match \
  -H 'Content-Type: application/json' \
  -d '{"selected_keyword_ids": ["kw_1", "kw_3"]}'
Expected: 10–15 keywords returned; match endpoint returns one of the 3 slot IDs with reasoning.

Phase 3: Asset Pipeline
Goal: Generate Tripo 3D models and assign ElevenLabs voices before publishing each slot.

Changes
backend/services/tripo_service.py — Async Tripo V2 API: POST generate task → poll → download .glb → save to game/public/models/generated/{slot_id}/{character_id}.glb. Retry up to 3×; fallback = copy one of the existing cached models (fenn.glb, victoria.glb, oliver.glb) based on gender/age match.
backend/services/voice_matcher.py — Curated voice bank (hardcoded dict of 10–15 ElevenLabs voice IDs with age/gender/tone metadata). Score voices against suspect profile; assign best fit. Fallback = default voice per age+gender bucket.
backend/db/schema.sql — asset_status table: (slot_id, character_id, model_path, voice_id, model_status, voice_status, retry_count).
Update daily_job.py — After story generation: run asset pipeline for each suspect; update asset_status; publish slot only if ≥2/3 suspects have playable assets (fallbacks count).
Update GET /daily-slots response — Include suspects[].model_url and suspects[].voice_id.
Verification
curl -X POST http://localhost:8000/admin/generate-daily-slots
curl http://localhost:8000/daily-slots | jq '.slots[0].suspects[].model_url'
ls game/public/models/generated/
Expected: .glb files present on disk; model_url paths point to them; voice_ids are real ElevenLabs IDs.

Phase 4: Session & Interrogation
Goal: Dynamic Claude interrogation using ChromaDB world context; full session lifecycle.

Changes
backend/agents/character.py — Per-suspect interrogation: query world_{slot_id} ChromaDB collection for character profile + relevant evidence → build context → Claude streaming response. Also query literary_corpus for Detective's Instinct if similarity ≥ 0.75.
backend/agents/evaluator.py — Evaluate final accusation: retrieve WorldState from SQLite; compare accused vs. killer_id; Claude explains verdict + missed clues.
backend/api/routes.py — Add endpoints:
POST /sessions/start — body: {slot_id}; return {session_id}
POST /sessions/{id}/interrogate — body: {character_id, message}; return {response, character_name, detective_instinct?}
GET /sessions/{id}/state — return current session state
POST /sessions/{id}/accuse — body: {character_id, reasoning}; return verdict
backend/db/schema.sql update — sessions table: (session_id, slot_id, started_at, state JSON)
